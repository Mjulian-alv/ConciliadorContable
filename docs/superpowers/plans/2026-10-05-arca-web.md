# ArcaCliente web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar conciliación ARCA/proveedores web reutilizando backend y aislando el homologador.

**Architecture:** Biblioteca neutral con las fuentes existentes, host Blazor en servidor,
persistencia SQL complementaria y archivos aislados por sesión. Login contra usuarios actuales.

**Tech Stack:** .NET 10 ASP.NET Core Blazor, Core .NET 8, SQL Server, Dapper, ClosedXML, SQLite para autenticación existente.

**Spec:** `docs/superpowers/specs/2026-10-05-arca-web-design.md` y especificación TAREA 00063.

## Global Constraints

- Worktree `arca-web`, rama `codex/arca-web`, TAREA 00064; no modificar AgrupadorConceptos.
- Primera entrega: ARCA/proveedor offline. Sin PyR, online ni comprobantes PRESEA web.
- No ejecutar operaciones contra la base productiva durante el desarrollo.
- Comentarios y mensajes en español; marcadores de tarea por bloque nuevo o modificado.
- SQL nuevo en `Data/*Storage.cs`, parametrizado, y transacciones para cambios múltiples.
- Reutilizar `ConciliacionService` y catálogo, sin duplicar el motor.

## Review Focus

1. Una fila inválida después de la muestra visible impide importar todo el lote incluido.
2. Recibos excluidos no requieren campos fiscales; un tipo desconocido no se excluye por defecto.
3. Cambios de formato, archivos, CUIT y directivas invalidan la conciliación anterior.
4. Dos usuarios no comparten archivos/resultados ni el usuario estático del escritorio.
5. Guardados simultáneos no pisan listas o configuraciones de otro usuario/perfil.
